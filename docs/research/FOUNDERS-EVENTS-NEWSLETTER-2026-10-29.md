## Newsletter diagnosis and release boundary

Empty JSON POSTs on 29 October returned 404 from both the same-origin subscription URL and direct canonical API URL. Current Laravel source already has both route prefixes; the likely causes are an outdated backend release or stale route cache, not a missing frontend URL. Hosting revision/cache evidence is still required to distinguish them. No real email address or subscription was submitted.

The frontend now hides internal route errors, preserves retry input, and shows success only after a successful response. Canonical/mounted backend tests and the production smoke script detect the missing route. The latter requires an intentional 422 validation response and never provides an email or consent. The eight checks can now detect a broken newsletter even when generic `/health` remains green.

Follow `DEPLOYMENT.md` for the exact backend release, migration, route-cache and controlled-inbox steps. GitHub CI and a merge do not prove production repair or delivery. Hostinger MCP is configured locally but its tools were not available; a CLI OAuth attempt could not complete because browser authorization was unavailable in this session. No hosting mutation was performed.
