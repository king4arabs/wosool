# Website and repository review — 8 October 2026

Scope: public `wosool.org`, the supplied GitHub repository, public/member API behavior, local installation, dependencies, and maintainer documentation. The production database, hosting account, mail provider, and authenticated production sessions were not accessed. This is a targeted engineering review, not a comprehensive penetration test.

## Findings addressed

| Finding | Change |
| --- | --- |
| Homepage used fixed membership counts, a sample testimonial, and dated sample events | Removed unsupported claims; homepage content uses independent API requests and events have real loading, error, retry, and empty states |
| Navigation was crowded at intermediate widths and the mobile menu lacked keyboard behavior | Raised the desktop breakpoint, added Escape/focus handling, current-page semantics, localized controls, and a scrollable mobile menu |
| Arabic typography and fixed-header spacing needed improvement | Applied the Arabic font before hydration, adjusted headings and page spacing, added mobile input sizing and reduced-motion support |
| Forgot-password page simulated a successful request | Implemented bilingual request/reset forms backed by Laravel's password broker, generic responses, throttling, token validation, and session revocation |
| Shared browser clients did not consistently send Sanctum's CSRF header | Centralized cookie bootstrap and decoded same-origin CSRF headers, request timeouts, and locale headers |
| Login accepted an unchecked redirect destination | Restricted post-login destinations to valid internal paths |
| Event lists could include ended events; detail/calendar visibility differed from listing rules | Added upcoming/past filtering, common public visibility/publishing rules, restricted public response fields, and ended-event RSVP rejection |
| Pages shared generic metadata and had no application sitemap/robots routes | Added page-specific titles/descriptions/canonicals, public sitemap, crawler exclusions, and account-route no-index headers |
| Local setup regenerated Laravel's encryption key | Made setup idempotent, preserved existing keys, and rejected production execution |
| Demonstration seeding could provision known fixture credentials on production | Added a production guard; existing production accounts still require a separate operator review |
| Backend test database could not run a vendor-specific migration expression | Replaced it with a portable conditional expression and repaired member fixtures to honor existing authorization rules |
| Company soft deletion and profile responses did not match implemented schema/contracts | Restored the model behavior, added a safe additive compatibility migration, and loaded the profile's user relationship |
| Frontend, PHP, and backend asset dependencies contained published advisories | Updated Next.js to 16.4.0 and refreshed compatible Composer/npm lockfile dependencies |
| README and operational docs disagreed with the repository | Rewrote setup, architecture, readiness, environment, testing, release, and security instructions; added a root CI workflow |

## Validation

Local checks use Node.js 24 and PHP 8.3, with an isolated in-memory SQLite test database.

- ESLint: no errors; seven pre-existing warnings in unrelated screens/hooks.
- TypeScript: passed.
- Frontend regression tests: four passed, covering redirects, session/CSRF requests, and event dates/order.
- Laravel tests: 71 passed, with 271 assertions.
- Demonstration entrepreneur dataset: 62 profiles validated.
- Next.js production build and backend Vite asset build: passed.
- Frontend production dependency audit: no known vulnerabilities at review time.
- Composer dependency audit: no security advisories after upgrading compatible dependencies, including Laravel 13.35.0.
- Backend npm audit: no known vulnerabilities after updating Axios and build dependencies. A `shell-quote` override selects the patched 1.12 line because the current `concurrently` 9 release pins a vulnerable version.
- The generated output includes the reset route, public sitemap, robots rules, and route-specific metadata.

## Remaining work and limits

- Production deployment requires the existing host's deployment mechanism. The repository CI validates code and does not deploy it. Verify the deployed commit, database migration, mail delivery, and session flows after rollout.
- Browser visual/accessibility checks and real email delivery were not performed in this environment. Follow the manual checks in `TESTING.md` on staging.
- Seven existing ESLint warnings remain. The previous lint configuration is deliberately retained while upgrading the runtime; a project-wide React Hooks rules migration is separate work.
- `npm audit` reports five high-severity **development-only dependency entries** from one `braces` advisory (`GHSA-vfj7-8cjw-p6xm`) propagated through the ESLint/fast-glob chain. The current resolver proposes a breaking ESLint-config downgrade, which was not applied. Production dependencies audit clean; review the toolchain when a compatible fix becomes available.
- Some secondary directories still contain seeded fallback content; the entrepreneur showcase is fictional by design. Confirm actual membership, sponsors, partners, and published news with the owner before using sample content as real-world evidence.
- Some application, contact, detail, and administrative screens remain Arabic-first. Shared navigation and recovery support Arabic and English, but this release is not a claim of complete localization.
- The regression suite validates application behavior on SQLite. Verify database-specific behavior on the production MySQL version during staging rollout.
