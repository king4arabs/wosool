# PHP security patch requirements — 2026-10-22

The Composer PHP requirement excludes versions affected by the PHP security advisory of 2026-10-21: https://www.php.net/archive/2026.php#2026-10-21-5

Supported patch floors are PHP 8.2.35 (where this project supports 8.2), 8.3.36, 8.4.27, and 8.5.12. Existing PHP 8.3 projects retain their 8.3 minimum branch. Repository CI/container pins are updated where present. Locked dependencies were audited against Packagist with the owner’s explicit authorization.

## Validation and limitations

- Local offline Composer strict validation passed, including manifest/lock consistency.
- These changes do not install PHP on a running host or prove application compatibility.
- Full application tests and live PHP-FPM/Apache version verification remain outstanding.
- Authorized Composer audit completed: no reported security advisories in the locked dependency set as of 2026-10-22.
- Do not bypass platform requirements during production installation.

## Deployment

Update the hosting PHP runtime to a patched release on its current supported minor branch, restart every PHP worker, and verify the web-serving runtime as well as the CLI. Rebuild containers with a fresh base image. Run the existing application suite and smoke checks before activating a release. Retain the previous application release for rollback, but keep the patched PHP runtime when rolling back application code. For legacy frameworks, plan compatibility upgrades separately; this patch does not upgrade Laravel.
