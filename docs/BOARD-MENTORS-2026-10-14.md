## Backend corrections and release requirements

- Board writes previously locked rows but accepted stale form data after acquiring the lock. A new integer `version` now protects PATCH and portrait POST operations. Successful writes increment it; stale writes return 409 before modifying the row or saving a photo. The public response does not expose this internal field.
- The admin interface passes the returned version through profile save, portrait upload and deferred publication. Reloading the list also refreshes the selected form, making recovery from a conflict possible.
- Fresh `eoa:install` runs now use `6 months`, matching the existing delivery model. Reinstallation remains insert-only for program settings and preserves local edits.
- Run `php artisan migrate --force` before activating the API release, then release the frontend and API together. Existing board rows receive version 1. Older open admin forms must be reloaded. There are no deletions or content imports required.
