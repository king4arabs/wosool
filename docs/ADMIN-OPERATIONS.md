## Find and manage services

`/admin/services` is the searchable directory for every administration area. The desktop sidebar also searches Arabic and English names and service descriptions. The page header keeps the directory one step away. On mobile, the menu button opens a searchable, grouped dialog with the same service links as desktop; Escape closes it and returns keyboard focus to the trigger. The service directory also filters by work area and offers daily shortcuts for applications, due relationships and Accelerator operations. Service names, descriptions and routes share `frontend/src/lib/admin-navigation.ts`; add future services there so navigation stays consistent.

The EOA administration page groups its available services into applications/participants, operations, content/partnerships and team/settings, with quick access to daily tasks. The menu includes only the capabilities already returned by the API; navigation never grants additional access. The selected section is preserved in `?tab=…`, supports browser back/forward and can be reopened directly. Unsupported or unauthorized sections fall back to Overview.

CRM and PR include a direct return to the service directory, clearable filters and readable touch controls. Select All, Open, Due or Unassigned to view the corresponding work queue. Unassigned means open records with no owner; due dates use Riyadh time and exclude completed relationships. Filter by stage, owner and high priority; sort by next follow-up, latest update or name. Filters, pagination and the selected record are preserved in the URL, including legacy `?due=1` links. Summary totals cover the entire CRM or PR workspace, while the result count reflects the filters. Records show their owner, brief/next step, localized follow-up date and urgency without opening the editor. Unavailable stage counts display a dash while data loads. Existing version checks, private notes and save behavior are preserved.

Release the matching API before this frontend: the collection endpoint now accepts allowlisted `view`, `priority` and `sort` parameters. This is an additive query change and needs no new database migration. The existing relationship tables must already be installed. Until the API update is deployed, older servers ignore these new filters and can show the unfiltered collection. Production verification must test these query parameters with an authorized administrator.


- The partner ecosystem shows bilingual search and the per-visit randomized rightward logo strip; category controls and the duplicate website directory are removed. Logos remain links to the organizations.
- The founders hero reads “تعرف على مجتمع المؤسسين في شبكة وصول”. Verified registration plus admin approval publishes both founder and co-founder profiles and creates their initial scorecard, regardless of featured status or score. Public card and grid views share the same paginated API collection; email, phone and private scores remain excluded. Repeated approval is idempotent; revoked approval removes public visibility.
- `/admin/crm` manages contacts, organizations, an assigned administrator, priority, follow-up date, campaign, relationship stage and private notes. `/admin/pr` adds the media pipeline and a published coverage URL. Activity notes persist with an author and timestamp. Existing messages, partners and content remain linked from these workspaces. These tools record work; saving does not send outreach.
- Relationship edits use a version check to reject conflicting saves. Admin-only API routes are under `/api/v1/admin/relationships`, with capped pagination and a bounded activity history. Audit entries contain workflow changes rather than duplicating contact details or note bodies.
- The main admin dashboard starts with overdue applications, unanswered messages, CRM/PR follow-ups and an actionable follow-up schedule. Analytics offers 7/30/90-day comparisons, daily account/application trends, current operational totals and CSV export. Approval rate means the share of applications created in the selected period whose current status is approved; it is not a historical decision conversion rate. Empty cohorts display no rate. Date windows use the API application timezone; follow-up dates use Riyadh.
